# Job Screening

## 目标

把岗位要求与用户已确认经历逐项对齐，输出可追溯的岗位排序，并在用户确认后写回岗位跟踪库。

## 前置条件

- 飞书官方 `lark-cli`、`lark-shared` 与 `lark-base` 可用。
- 用户提供个人信息库和岗位跟踪库链接。
- 需要联网读取岗位页面时使用 Agent 可用的浏览能力；页面不可读时退回 JD 文本。

## 输入

必填：

- 个人信息库链接；
- 岗位跟踪库链接；
- 岗位链接、粘贴的 JD，或岗位库内的筛选范围。

可选：目标方向、城市、公司、推荐数量、截止时间、投递数量限制和硬性排除条件。

## 默认工作流

1. 完整读取 [岗位筛选评分标准](references/scoring-rubric.md)。
2. 解析两个 Base 链接并读取真实表、字段、关联关系和目标视图。
3. 读取个人信息库中已确认的个人档案、教育、实习、经历素材、项目、技能、目标岗位和荣誉信息。
4. 获取 JD 原文；记录岗位名称、地点、链接、岗位方向、核心任务、技能和硬性门槛。
5. 按公司与岗位唯一性去重。同一岗位的多条来源优先保留官方独立 JD。
6. 建立“岗位要求—已有证据”映射，将每项标为强证据、弱证据、缺失证据或冲突证据。
7. 按评分标准计算分数和等级；硬门槛失败时应用等级上限。
8. 在同一筛选范围内排序，并给出第一/第二优先、补充投递或观察建议。
9. 展示拟写入岗位清单和推荐岗位明细的字段预览。
10. 用户确认后串行写入；依据返回结果报告成功数量。

## 查询规则

- 全量结论必须读完所需分页；`has_more=true` 时不能宣称全量最优或完整计数。
- 能在 Base 云端筛选、排序、聚合的操作优先在 Base 完成，不把未知范围的单页结果拉到本地后手工排名。
- 双向关联中的 record ID 只是连接键；最终输出必须回查用户可读的公司或岗位名称。
- 每次写入前重新读取字段，不能使用仓库、文档或上次会话中的 ID。

## 岗位库字段映射

### 岗位清单

公司/项目、当前状态、截止时间、剩余天数、紧急度、申请入口、推荐岗位、匹配度、匹配等级、投递建议、已投递、信息可信度、备注、最后更新、推荐岗位明细。

### 推荐岗位明细

岗位名称、关联公司、工作地点、岗位方向、JD摘要、JD或投递链接、与你的匹配点、主要短板/提醒、岗位匹配度、优先级、推荐序号、岗位确认状态、链接类型、站内检索关键词、核验日期、投递状态、备注、最后更新。

只写存储字段；更新时间等系统字段不作为普通值提交。

## 输出格式

```markdown
推荐结论：
1. [公司｜岗位] — [等级/分数] — [优先级]
2. [公司｜岗位] — [等级/分数] — [优先级]

| 岗位 | 核心任务 | 强证据 | 弱/缺失证据 | 硬门槛 | 建议 |
|---|---|---|---|---|---|

拟写入飞书：
| 数据表 | 记录 | 字段变化 |
|---|---|---|
```

## 质量与安全

- 不因岗位名称相似就判定匹配；必须阅读任务与门槛。
- 不为提高分数添加个人信息库没有的技能或结果。
- 岗位信息含日期时记录核验日期和链接类型。
- 投递状态与“已投递”字段由用户事实决定，不擅自修改。
- 所有写入先预览并确认；第一版不删除任何记录、字段或表。

## 停止与恢复

- JD 页面不可读：使用岗位库已有摘要，或请用户粘贴 JD。
- 岗位来源互相冲突：优先官方信息，并把冲突写入提醒。
- Base/表候选不唯一：列出候选供用户选择。
- 分页未完成：继续读取；无法完成时只报告已读范围，不给全量排名。
- 个人事实不足：降低证据等级并列出需补充项，不猜测。
- 用户未确认写入：返回预览并停止。
