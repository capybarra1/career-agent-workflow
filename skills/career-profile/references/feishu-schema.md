# 个人求职信息库 Schema

本文件是新建个人求职信息库时的结构基线。连接已有库时，以运行时读取到的真实结构为准；发现差异后先报告，不自动迁移。

## 1. 个人档案

| 字段 | 类型 | 说明 |
|---|---|---|
| 姓名 | 文本（主字段） | 对外使用的姓名 |
| 手机号 | 文本 | 保留区号与格式 |
| 邮箱 | 文本 | 求职联系邮箱 |
| 所在城市 | 文本 | 当前常驻城市 |
| 主要求职方向 | 多选 | 当前主申方向 |
| 候补方向 | 多选 | 可接受的次级方向 |
| 核心定位 | 文本 | 一句话职业定位 |
| 差异化优势 | 文本 | 有事实支撑的差异点 |
| 预计毕业时间 | 文本 | 推荐 `YYYY-MM` |
| 应届届别 | 文本 | 例如 `2027 届` |

## 2. 教育经历

字段：学校（主字段）、学历、专业、研究方向、起止时间、核心课程与成果、信息状态、备注。

- 学历：硕士 / 本科 / 其他。
- 信息状态：已确认 / 待补充 / 待确认。

## 3. 实习经历

字段：经历名称（主字段）、公司、品牌或业务、职位、起止时间、核心场景、主要职责、阶段与结果、适用岗位、信息状态、备注。

- 适用岗位：AI产品经理 / 数据产品经理 / 平台产品经理 / 智能座舱产品经理 / 用户研究。
- 信息状态：已确认 / 待补充 / 待确认。

## 4. 经历素材

字段：素材标题（主字段）、所属经历、模块、背景与任务、个人行动、结果与产出、量化证据、技术与方法关键词、适用岗位、信息状态、来源与备注。

- 模块可按用户经历扩展；创建模板时提供数据平台、用户研究、AI Agent、工单闭环、模型评测、座舱产品、用户反馈、AI陪伴、IoT联动、科研实验。
- 信息状态：已确认 / 待补充量化 / 待确认。

## 5. 项目经历

字段：项目名称（主字段）、项目类型、时间、研究或产品目标、个人职责、方法与工具、成果与证据、适用岗位、信息状态、备注。

- 项目类型：企业项目 / 科研项目 / 产品设计 / 课程项目 / 个人项目。
- 适用岗位：AI产品经理 / 数据产品经理 / 智能座舱产品经理 / 用户研究 / 交互设计。
- 信息状态：已确认 / 待补充 / 待确认。

## 6. 技能与工具

字段：技能项（主字段）、类别、能力说明、熟练程度、对应证据、适用岗位、备注。

- 类别：产品设计 / AI产品 / 用户研究 / 数据分析 / 开发与联调 / 设计工具 / 协作工具 / 人因实验。
- 熟练程度：有项目证据 / 基础 / 待确认。

## 7. 目标岗位

字段：岗位方向（主字段）、目标岗位示例、优先级、核心卖点、简历重点、需补强或待核验、推荐页数、备注。

- 优先级：主申 / 重点 / 补充 / 冲刺。
- 推荐页数：一页 / 两页 / 按JD决定。

## 8. 荣誉奖项

字段：荣誉或奖项（主字段）、类别、级别与等级、时间、信息状态、来源与备注。

- 类别：荣誉称号 / 奖学金 / 竞赛获奖 / 项目结题。
- 信息状态：已确认 / 待补充时间 / 待核验。

## 运行时规则

1. 使用 `lark-cli base +url-resolve --url "<用户提供的链接>" --as user` 解析链接。
2. 写入前读取 Base、数据表和字段；不得在仓库或输出中保存 Base Token、table ID、field ID。
3. 已有库包含额外数据表时忽略，不读取、不写入、不删除。
4. 缺少必需表或字段时展示差异并停止写入；只有用户明确同意后才能补建。
5. 只向可写存储字段写值；系统字段、公式、关联与附件遵守飞书官方 Skill 的专用规则。
6. 所有新增或更新先展示表名、目标记录和字段值；用户确认后再执行。
