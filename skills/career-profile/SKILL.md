# Career Profile

## 目标

把用户提供的求职事实整理到个人飞书多维表格中。先确认事实和目标表，再展示写入预览；未经确认不得写入。

## 前置条件

- 飞书官方 `lark-cli` 可用。
- `lark-shared` 与 `lark-base` Skills 已安装。
- 访问用户资源时显式使用用户身份。

缺少 CLI 或授权时暂停业务操作，按 `lark-shared` 完成安装、配置或 split-flow 授权。

## 输入

必填：

- 个人求职信息库链接；新用户可以明确要求创建模板。
- 至少一种事实材料：原简历、项目记录、作品说明、文档或本人补充。

可选：目标岗位方向、指定更新的数据表、隐私限制、只读审计要求。

## 默认工作流

1. 完整读取 [个人求职信息库 Schema](references/feishu-schema.md)。
2. 解析 Base 链接；没有链接且用户要新建时，才创建模板。
3. 列出真实数据表和字段，按名称匹配，不使用历史 ID。
4. 读取用户材料，把每项内容标为：已确认、待补充、待确认、不可外发。
5. 按真实项目边界归类，不把同一项目的调研、方案、原型和测试拆成互不相关的经历。
6. 对重复记录执行读取比对；目标唯一时更新，无法唯一定位时请求用户选择。
7. 输出写入预览，包含目标表、创建/更新动作、字段和值。
8. 只有用户明确确认后，才使用 `lark-cli base +record-upsert` 或适合的批量写入命令。
9. 依据写入返回报告成功记录；返回不明确时再读回核验。

## 表格路由

| 输入内容 | 目标表 |
|---|---|
| 姓名、联系方式、求职方向、定位 | 个人档案 |
| 学校、专业、学历、课程 | 教育经历 |
| 公司、职位、业务、实习阶段 | 实习经历 |
| 一段经历内的任务、行动、结果 | 经历素材 |
| 企业、科研、课程或个人项目 | 项目经历 |
| 方法、软件、开发与研究能力 | 技能与工具 |
| 主申方向、简历重点、补强项 | 目标岗位 |
| 荣誉、奖学金、竞赛、结题 | 荣誉奖项 |

## 事实与质量规则

- 不编造经历、数字、技能、项目状态或个人所有权。
- 团队结果必须与个人贡献分开；根据事实使用主导、负责、参与或协助。
- 量化信息至少能说明对象和口径；无法核验时标为待补充，不写成确定结果。
- 不把 Demo、POC、UAT、测试或灰度写成正式上线。
- 手机号、邮箱及隐私内容只写入用户自己的 Base，不复制到仓库、示例或日志。
- 现有库中的额外表不属于本 Skill 的写入范围。

## 输出格式

```markdown
当前判断：
- 已确认事实：...
- 待确认事实：...

拟写入：
| 数据表 | 动作 | 定位字段 | 写入内容 |
|---|---|---|---|

需要你确认：是否按以上预览写入？
```

写入后报告 Base 标题、数据表、成功数量、未写入项与原因，不输出任何 Token 或内部 ID。

## 停止与恢复

- Base 候选不唯一：列出标题供用户选择，不猜。
- 表或字段缺失：展示差异，不自动改 Schema。
- scope 不足：按 `lark-shared` 发起最小权限授权，不降级为 bot 代替用户。
- 信息冲突：并列展示来源内容并请求用户确认，不覆盖旧值。
- 用户没有确认写入：保留预览，停止在写入前。
